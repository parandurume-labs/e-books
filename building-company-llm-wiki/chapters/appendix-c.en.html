APPENDIX C

Where people get stuck

Start from the symptom. The cause comes after

about 14 min

If you are here, something is already stuck. So instead of an explanation, the symptoms come first. Find the row in the table below that looks most like what is on your screen and follow the link on the right. Tool screens and menu names are as of July 2026.

Sync: the AI cannot read the files

Symptom. You connected the vault folder and the AI says "I cannot find that file". Or you clearly have 100 notes and it reads five or six and says the rest are not there. Open the folder and every filename is visible.

Cause. OneDrive keeps files you rarely touch in the cloud and leaves only the name behind. Turn on the status column in File Explorer and you will see a cloud icon on them. Double-click and it downloads and opens, but when a program reads it, none of that happens and it simply fails. This is the pitfall from Chapter 6. It is also the single most common place people get stuck in practice.

  1. Right-click the vault folder

    In File Explorer, right-click the top-level vault folder (for example Solbit Tech Wiki).

  2. Turn on "Always keep on this device"

    If it is not in the menu, it is under "Show more options". It applies to every subfolder, so doing it once at the top is enough.

  3. Wait until the status icons turn into green circles

    Even several hundred notes take a few minutes. If one cloud icon is left, it is not done.

  4. Turn off Storage Sense

    Under Windows Settings, "System → Storage → Storage Sense", turn off the item that pushes unused cloud files back up. Leave it on and the same symptom comes back in a few weeks.

What "but it worked yesterday" really is

When you first set things up, the files were just created, so they are all local. So it works. A few weeks on, notes you have not touched go up to the cloud one by one, and from then the AI reads only some of them. The worse half is that the AI does not say "they are missing". It answers from what it read. The answer sounds right and nobody notices.

Once a month, sweep the vault folder for cloud icons. Thirty seconds does it.

Solbit Tech in practice: the report they believed for three weeks

Lee, the CTO, set up the weekly check and got "no problems" three weeks running. In reality only twelve notes in the vault were being read. Everything else had a cloud icon.

They found it by accident. Park asked "why doesn't the Daesung Logistics note come up in search", and only then did anyone look at the folder status.

The lesson here is not the setting. It is that you have to be able to tell "nothing to report" from "could not read anything". Make the first line of the report carry the number of notes read. A sudden drop in that number is how you catch it.

YAML: the frontmatter breaks

Symptom. You open a note and what is between the --- markers shows as literal text in the body instead of a table. Or the dashboard and the validation script keep skipping that one note.

Cause. Frontmatter is a format called YAML, and YAML is very sensitive about a few characters. The five below cover nearly everything that happens in practice.

# 1) A colon inside a value. With a space after it, YAML takes it for a key
title: Warebot: logistics automation      (broken)
title: "Warebot: logistics automation"    (fine)

# 2) A wikilink. Starting with a bracket makes it a list
owner: [[Kim]]                   (broken)
owner: "[[Kim]]"                 (fine)

# 3) The space after the colon. Run them together and the key is not seen
status:진행                      (broken)
status: 진행                     (fine)

# 4) Dates. A one-digit month or day reads as text, not a date
due: 2026-8-8                    (sorts wrong)
due: 2026-08-08                  (fine)

# 5) Indentation. Tabs do not work, only spaces
pdm_uses:
	- "[[Warebot]]"                 (a tab, so broken)
pdm_uses:
  - "[[Warebot]]"                (two spaces, fine)

There is one more thing people hit often. The --- has to be the very first line of the file. One blank line in front of it and Obsidian does not read it as frontmatter. Paste from somewhere else and invisible characters sometimes ride along in front too. If you suspect that, delete the first line and type --- again by hand.

Values need quotes only sometimes

Values like status: 진행 or funder: MOTIE are fine as they are. Quotes are needed only for values that start with or contain a colon, a bracket, a brace or a hash. If you are unsure, wrapping everything in double quotes causes no harm.

How to check. Switch Obsidian from edit mode to reading mode with the control at the top right. If the frontmatter shows as a properties table, it is fine. If it shows as literal text, it is broken. To check many notes at once, run the validation script from Appendix B. It catches them as "no frontmatter".

Sync conflict copies appear

Symptom. Files like Warebot 1.md or Warebot-DESKTOP-A1B2.md turn up in the folder. Or a whole paragraph you wrote yesterday is gone.

Cause. The same file was edited in two places at once. Two people opening the same note is the most common, and after that comes a scheduled task running overnight touching a file somebody left open. You come in the next morning and there is one extra copy with no obvious explanation.

How to prevent itWhy it works
Automation writes to _reports/ and _moc/, nowhere elseThe notes people open and the files automation writes never overlap
During a meeting, only one person opens the meeting noteThere is no real-time co-editing. Merging afterwards is too late
Close the tab when you finish editing a noteSometimes just having it open counts as editing
Keep notes smallOne file that gathers several people's interests conflicts often

Cleaning up a conflict copy you already have. Keep to the order.

  1. Open both files side by side

    Open one in a right-hand split in Obsidian and you see them together. Decide which is newer by content, not by modification time.

  2. Move sentences that exist on only one side into the original

    There is often a paragraph that exists only in the conflict copy. Skip this step and that content disappears.

  3. Delete the copy only after you have checked what you moved

    Delete before checking and there is no way back. It stays in the OneDrive recycle bin for 30 days, but finding it is a nuisance.

  4. Set updated to today's date

    A merge is an edit too. Leave that field stale and the note gets flagged as abandoned.

Links break

Symptom. [[Warebot]] shows in grey and clicking it only offers to create a new note. Or broken links in the weekly check report suddenly jumped by twenty.

The cause is one of three.

  • The note does not exist yet. That is not a fault. A grey link in Obsidian marks "there should be a note here and there is not yet", and it works as your list of what to fill in next.
  • Something was renamed in File Explorer. Rename inside Obsidian and every link pointing at that note follows. Rename in Explorer or on the SharePoint web and nothing follows. A batch of broken links appearing in the report is usually this.
  • Somebody else renamed it before it synced. Reference a note before the rename comes down and it briefly disagrees. It resolves itself once the sync finishes.

Names may change, ids may not

Titles change. Warebot may become "SmartFactoryBot". Leave id: PRD-001 alone and the decision notes and reports that cite that note as evidence keep matching. Rename only inside Obsidian. That one habit removes most of the problems in this section.

How to fix them. For links that are already broken, the validation script in Appendix B gives you both the file and the target name. Take that list and pick one of two options. Create the note and fill it, or correct the link to the current name. If you do not want to do either, leave the link rather than deleting it. A broken link is a signal telling you where a gap is, and deleting it deletes the signal.

The scheduled task does not run

Symptom. It comes in two shapes. Either there is no run history at all, or there is a history and the result is one line saying "no record" or an empty report. The second is far more dangerous, because you spend weeks believing "the check found no problems".

A remote run cannot reach a local folder

This is the core constraint from Chapter 14. A scheduled task running remotely cannot see folders inside your PC. It only handles files that live in a connector or in your Claude account. But your vault is a local folder like C:\Users\...\OneDrive - Solbit Tech\Solbit Tech Wiki\.

If a job needs local files, that job runs locally only. Which means the PC has to be on at that hour with the desktop app alive. If it is off, that round simply passes.

Work through the checks in this order.

What to checkIf not
Does this job have to read or write vault filesThen it is a local run (route A). Leave the PC on at that hour or move the time
If you meant it to run remotely, is a connector attachedAttach the SharePoint or OneDrive connector. Without one it cannot read the vault and finishes empty-handed
Is it stuck waiting for approvalA job that hit "needs confirming" at 3am sits there until morning. Restrict what it writes to _reports/ and switch it to automatic approval
Does the result carry evidence note namesIf not, it could not read the vault and made it up. Put the evidence requirement in the prompt

The fastest check is this. Run the same prompt by hand in the chat window once. If it works by hand and comes back empty on a schedule, the problem is the run environment. If it comes back empty by hand too, the problem is the prompt or the vault. That one run halves the search.

A device for noticing a breakage. Scheduled tasks fail silently. Nobody notices an alert that did not arrive. So make sure one of them arrives every week without fail. Even with nothing to say, let the single line "nothing unusual this week" come through. That one line is the signal that the system is alive. Two weeks with nothing at all and something is broken.

The script does not run

Symptoms and causes together here. What goes wrong with Python scripts is more or less a fixed list.

What you seeHow to fix it
'python' is not recognized as an internal or external commandRun it with py instead of python. If that still fails, you did not tick "Add to PATH" during install
The Microsoft Store opens instead of PythonUnder Settings, "Apps → Advanced app settings → App execution aliases", turn the python entries off

To see whether a registered task really ran, look at "Last Run Result" in the Task Scheduler list. 0x0 means a clean exit. The validation script exits with 1 when there are ERRORs, so a non-zero value does not mean failure. What actually matters is whether a file with today's date appeared in _reports/.

The answers are odd

Symptom 1. It states numbers that are not in the vault, convincingly. That happens because there are no rules. The AI fills a blank when it meets one. Put the CLAUDE.md from Appendix B at the vault root, and check in particular that the two lines "if you do not know, write 확인 필요" and "attach an evidence note to every number" are in it. Every time it makes the same mistake twice, add a line to the facts that are easy to get wrong section.

Symptom 2. Everything you ask comes back "no record". This is not a fault, it is an honest answer. With only a dozen notes in the vault, of course there is no evidence. This is a place to fill notes, not a place to fix the prompt. Run meeting note structuring for three weeks in the order Chapter 16 lays out and the answers change.

Symptom 3. It states old values as fact. That happens when the same entity has different values written in two places. WareTwin's TRL being 4 in one place and 6 in another is the case. Schedule the monthly contradiction scan from Appendix B and it gets caught before anything goes out. Do not have the AI pick between the two. That is a person's call.

Symptom 4. It does not know about notes you made recently. Either the sync has not finished, or it is the cloud-only file problem from the first section. Check for cloud icons before you reconnect the folder.

Permissions and confidentiality do not line up

Symptom. A colleague cannot open the vault folder at all. Or a note you just made is invisible to somebody else. It goes the other way too: the onboarding pack you gave a new hire had contract pricing mixed into it.

Cause. The vault sits in a Teams team's file folder, and who can see it is decided entirely by that team's membership. Obsidian decides nothing. Anyone in the team sees the whole folder unless you block them specifically.

  1. If somebody cannot open it, check the team invitation first

    The folder has to be visible in the Files tab in Teams before desktop sync will attach. Right after an invitation it takes a few minutes to come down.

  2. Keep some confidential material in a different team's folder, outside the vault

    Carving one file out of a team and giving it different permissions is a nuisance. Contract pricing and salary figures are safer in another team's folder from the start.

    Making a Confidential/ folder inside the same vault is forbidden in Chapter 10. The note disappears from where it belongs and drops out of aggregates like the customer list entirely. What this step means is a folder outside the vault, in a team with different permissions.

  3. Use the confidential field to stop the AI

    This field is not a device for stopping people. It is a device for stopping things leaking into output. That is why the onboarding pack and proposal prompts carry a confidentiality filter.

  4. Do not present a pre-contract customer as a track record

    Daesung Logistics is that case. Confidentiality accidents mostly happen when "not yet" gets written down as "already done".

A prompt is not a boundary

"I told the AI to leave confidential material out, so we are safe" is the most dangerous thought here. A prompt is a request, not a block. One slip, whether a mistake or a missing prompt line, and it goes straight out.

The real boundary is file permissions. Values that must not leave either do not go in the vault or move to another folder. Fields and prompts are a second net laid on top of that.

Nothing shows on screen

Mermaid code shows as literal text. Check that the first line of the code fence is ```mermaid. Mixed case or a stray space and you get no diagram. The next most common cause is a colon inside a gantt task name. A colon separates the name from the attributes, so one inside the name breaks the syntax. That is why the dashboard script in Appendix B replaces colons in names with spaces.

Notes are missing from a table or board. Compare the folder path and the field names character by character. Sources/20-Projects and Sources/20-Project are different. Check the value side too. status: 진행중 is outside the controlled vocabulary, so no filter catches it. The status values for projects and opportunities are just the five: 기획, 진행, 검토, 완료, 보류.

The graph view is a hairball. Not a fault. Past 100 notes the whole-vault graph becomes unreadable by nature. What you show in a meeting is not the graph view but a Mermaid diagram drawn with only what you need. That is the distinction Chapter 15 draws.

If it still will not come loose

Try three things in order. One. Look for cloud icons left in the vault folder. Half of this appendix ends there. Two. Take one of the problem notes and check its frontmatter in reading mode. Three. Run the validation script from Appendix B and read the ERROR list. The symptom may be one thing, but the cause is often already on that list with a name attached.
