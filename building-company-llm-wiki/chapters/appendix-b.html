# 솔빛테크 위키 · AI 작업 규칙

마지막 수정: 2026-07-30 · 고치는 사람: 김대표
이 파일은 사람만 고친다. AI는 제안만 한다.

## 0. 이 볼트가 무엇인가

- 솔빛테크의 회사 지식을 담은 볼트다.
- 회사 사실은 Sources/ 아래 노트에만 있다. 그 밖에서 사실을 가져오지 않는다.
- 클래스·관계·필드·어휘의 정의는 _ops/01-온톨로지-설계서.md 에 있다.
  판단이 갈리면 그 문서를 따른다.
- 규칙끼리 부딪히면 번호가 낮은 쪽이 이긴다.

## 1. 절대 규칙 (예외 없음)

1. 없는 사실을 채우지 않는다. 볼트에 없으면 「기록 없음」이라고 답한다.
2. 근거 없는 수치는 쓰지 않는다. 대신 「확인 필요」라고 쓴다.
3. 답에는 근거 노트 이름을 함께 적는다. 근거를 못 대는 문장은 뺀다.
4. 기존 노트와 어긋나는 내용을 발견하면 고치지 말고 「모순」으로 따로 보고한다.
5. 사람 이름과 직함을 추측해 붙이지 않는다. 원문 표기를 그대로 쓴다.
6. confidence: draft 인 노트는 대외 문서의 근거로 쓰지 않는다.

## 2. 필드와 어휘

- 마감 날짜는 언제나 due 다. 다른 이름을 만들지 않는다.
- 관계는 pdm_uses / pdm_output_of / pdm_intent_of 를 쓴다. 담당자는 owner 로 적는다.
- 관계 필드의 값은 "[[노트이름]]" 형태의 링크로 적는다. 여러 개면 줄을 나눈다.
- status: 제품은 기획 / 개발 / 운영 / 중단. 과제와 기회는 기획 / 진행 / 검토 / 완료 / 보류.
- confidence: draft 또는 reviewed. 그 밖의 값을 만들지 않는다.
- 설계서에 없는 필드를 새로 만들지 않는다. 필요하면 사람에게 제안만 한다.

## 3. 파일을 쓰는 규칙

- 스스로 새 파일을 만들어도 되는 곳은 _reports/ 와 _moc/ 두 곳이다.
- Sources/ 아래의 노트는 표로 먼저 보여주고 승인을 받은 뒤에 만들거나 고친다.
- _ops/ 아래와 이 파일은 사람만 고친다.
- 새로 만드는 노트에는 confidence: draft 와 오늘 날짜(KST)의 updated 를 넣는다.
- 자동 생성 파일 맨 위에 다음 문구를 넣는다:
  「이 파일은 자동 생성됩니다. 직접 고치면 다음 실행 때 사라집니다.」

## 4. 기밀

- confidential 값: 공개 / 사내 / 대외비. 값이 없으면 사내로 본다.
- 대외비 노트의 회사 이름을 대외 문서에 그대로 쓰지 않는다.
  계약 전 고객은 「국내 물류기업」처럼 가려서 쓴다.
- 개인정보, 계정과 비밀번호, 급여와 인사 자료는 볼트에 두지 않는다.
  발견하면 작업을 멈추고 사람에게 알린다.

## 5. 틀리기 쉬운 우리 회사 사실

문서마다 값이 어긋나 사고가 났던 것들이다. 아래 적힌 쪽이 맞다.

- 웨어트윈의 TRL 은 4다. 옛 자료의 6은 과장으로 정정됐다. 근거: DEC-2026-0715-TRL정정.
- 대성물류는 계약 전이다. 납품 실적이나 레퍼런스로 쓰지 않는다.
- 픽뷰는 실증 데이터가 없다. 제안서 근거로 쓰지 않는다.
- 창고봇의 운영 시작은 2023년 4월이다. 「2023년 출시」로 반올림하지 않는다.
- 「이대표」와 「김대표」는 확인 전까지 다른 표기로 둔다. 합치지 않는다.
- CAP-객체인식은 PRJ-2025-스마트물류의 산출물이다. 자체 개발로 쓰지 않는다.

## 6. 답할 때

- 볼트에 답이 없으면 「기록 없음」이라고 먼저 말하고,
  그 사실을 어느 노트에 적으면 되는지 알려준다.
- 표로 답할 수 있으면 표로 답한다. 길게 늘이지 않는다.
- 승인이 필요한 작업은 먼저 보여주고 기다린다. 미리 실행하지 않는다.

# _ops/scripts/validate.py
# 볼트 규칙을 코드로 확인한다. 외부 라이브러리 없음.

import re, sys, datetime
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]   # 볼트 최상위
TODAY = datetime.date.today()
STALE_DAYS = 30

# 클래스별 필수 필드. 1층 설계서와 이 표가 어긋나면 설계서가 정본이다.
# 공통 필수는 class·id·updated 셋이고, 그 뒤가 클래스마다 다른 부분이다.
REQUIRED = {
    # 9장의 뼈대 클래스 넷
    "제품":     ["class", "id", "updated", "status", "owner", "since"],
    "기술역량": ["class", "id", "updated", "trl", "evidence"],
    "과제":     ["class", "id", "updated", "period", "funder", "budget"],
    "기회":     ["class", "id", "updated", "stage", "due"],
    # 9장의 보조 클래스 셋
    "조직":     ["class", "id", "updated"],
    "사람":     ["class", "id", "updated"],
    "결정":     ["class", "id", "updated", "date"],
    # 클래스가 아니라 40-Worklog 의 노트 종류다. 12장 참조.
    # 빠지면 「class 값이 설계서 목록 밖」 ERROR 가 쏟아지므로 여기 함께 적는다.
    "회의록":   ["class", "id", "updated", "date"],
    "업무로그": ["class", "id", "updated", "owner"],
}

# status 어휘는 클래스마다 다르다. 전역 한 벌로 두면 오탐이 쏟아진다.
STATUS_ENUM = {
    "제품": {"기획", "개발", "운영", "중단"},
    "과제": {"기획", "진행", "검토", "완료", "보류"},
    "기회": {"기획", "진행", "검토", "완료", "보류"},
}

# 금지 이름. 뜻이 같은데 이름이 제각각이면 못 센다. 아래는 전부 나쁜 예다.
FORBIDDEN = {"deadline": "due", "마감일": "due",
             "uses_tech": "pdm_uses", "tech_used": "pdm_uses",
             "사용기술": "pdm_uses"}

findings = []
metas = []                                   # 뒤의 지표 계산이 이 목록을 쓴다
def add(level, where, msg):
    findings.append((level, where, msg))

FM = re.compile(r"\A---\n(.*?)\n---", re.S)

def frontmatter(text):
    m = FM.match(text)
    if not m:
        return None
    meta, key = {}, None
    for line in m.group(1).splitlines():
        if line.lstrip().startswith("-") and key:      # 목록 항목
            meta.setdefault(key, []).append(line.strip(" -").strip('"'))
            continue
        m2 = re.match(r"([A-Za-z_가-힣]+):\s*(.*)$", line)
        if m2:
            key = m2.group(1)
            val = m2.group(2).strip().strip('"')
            meta[key] = val if val else []
    return meta
notes = {p.stem: p for p in (ROOT / "Sources").rglob("*.md")}
LINK = re.compile(r"\[\[([^\]|#]+)")

for stem, path in sorted(notes.items()):
    where = path.relative_to(ROOT).as_posix()   # 파일명이 아니라 볼트 상대경로
    text = path.read_text(encoding="utf-8")
    meta = frontmatter(text)

    if meta is None:
        add("ERROR", where, "프론트매터 없음")
        continue

    metas.append(meta)                             # 지표용. 여기서 모아 둔다

    cls = meta.get("class")
    if cls not in REQUIRED:
        add("ERROR", where, f"class 값이 설계서 목록 밖: {cls!r}")
        continue

    for field in REQUIRED[cls]:                       # 1. 필수 필드
        if not meta.get(field):
            add("ERROR", where, f"필수 필드 누락: {field}")

    st = meta.get("status")                            # 2. 통제 어휘
    if st and st not in STATUS_ENUM.get(cls, set()):
        add("ERROR", where, f"{cls}의 status 어휘 밖: {st!r}")

    for bad, good in FORBIDDEN.items():                # 3. 금지 이름
        if bad in meta:
            add("ERROR", where, f"금지 이름 {bad} 사용. {good} 로 바꿀 것")

    for target in set(LINK.findall(text)):             # 4. 끊어진 링크
        if target.strip() not in notes:
            add("ERROR", where, f"끊어진 링크: [[{target.strip()}]]")

    upd = meta.get("updated", "")                      # 5. 오래된 노트
    if not re.fullmatch(r"\d{4}-\d{2}-\d{2}", str(upd)):
        add("ERROR", where, "updated 가 YYYY-MM-DD 형식이 아님")
    elif st in ("진행", "운영"):
        age = (TODAY - datetime.date.fromisoformat(upd)).days
        if age > STALE_DAYS:
            add("WARN", where, f"{age}일째 그대로 (status: {st})")

    if meta.get("confidence") == "draft":
        add("INFO", where, "사람 검토 대기")

17장은 지표를 개수가 아니라 비율로 남기라고 합니다. 노트가 늘면 개수는 저절로 늘기 때문입니다.

# 지표는 개수가 아니라 비율로 남긴다

def gr_body(text):                    # 프론트매터를 뺀 본문
    m = FM.match(text)
    return text[m.end():] if m else text

total = len(notes)
if not total:                                  # 도입 첫날 빈 볼트에서 0 으로 나누지 않게
    add("INFO", "_", "노트가 없습니다. 지표는 노트가 생긴 뒤부터 셉니다")
    total = 1
grounded = 0
for p in notes.values():
    t = p.read_text(encoding="utf-8")
    # 정의 그대로: 본문에 위키링크가 있거나 evidence 가 채워진 노트
    if LINK.search(gr_body(t)) or (frontmatter(t) or {}).get("evidence"):
        grounded += 1
reviewed = sum(1 for m in metas if m.get("confidence") == "reviewed")

add("INFO", "_", f"근거 있는 노트 {grounded}/{total}"
                 f" ({grounded * 100 // total}%)")
add("INFO", "_", f"검증된 노트 {reviewed}/{total}"
                 f" ({reviewed * 100 // total}%)")
order = {"ERROR": 0, "WARN": 1, "INFO": 2}
findings.sort(key=lambda f: (order[f[0]], f[1]))
n = {lv: sum(1 for l, _, _ in findings if l == lv) for lv in order}

lines = [f"# 볼트 점검 {TODAY}", "",
         f"- ERROR {n['ERROR']} · WARN {n['WARN']} · INFO {n['INFO']}",
         f"- 검사한 노트 {len(notes)}개", ""]
for lv in ("ERROR", "WARN", "INFO"):
    group = [(w, m) for l, w, m in findings if l == lv]
    if not group:
        continue
    lines.append(f"## {lv} {len(group)}건")
    lines += [f"- `{w}` {m}" for w, m in group]
    lines.append("")

(ROOT / "_reports").mkdir(exist_ok=True)
(ROOT / "_reports" / f"점검-{TODAY}.md").write_text(
    "\n".join(lines), encoding="utf-8")

# 15장의 추이 그래프 재료. 한 줄씩 누적한다.
# 열: 날짜, ERROR, WARN, INFO, 전체 노트 수, 검증된 노트 비율(%)
# 마지막 열이 15장이 그리는 선이다. 이 열이 없으면 그래프를 못 그린다.
with (ROOT / "_reports" / "validate-history.csv").open(
        "a", encoding="utf-8") as f:
    f.write(f"{TODAY},{n['ERROR']},{n['WARN']},{n['INFO']},"
            f"{len(notes)},{reviewed * 100 // total}\n")

sys.exit(1 if n["ERROR"] else 0)

# 원문 구조화

## 언제 쓰나
- 회의가 끝나고 메모를 볼트에 넣을 때
- 고객에게 받은 문서나 공고문을 볼트에 넣을 때

## 입력
- 원문 텍스트 또는 파일 경로 하나
- 없으면 시작하지 않는다. 원문을 달라고 요청한다

## 절차
1. 원문을 먼저 저장한다.
   회의 메모는 Sources/40-Worklog/, 밖에서 받은 자료와 녹취는
   Sources/90-Reference/ 에 넣는다.
   파일명은 YYYY-MM-DD-제목 형식으로 한다.
2. 원문에서 아래 네 가지를 뽑는다.
   - 결정: 「~하기로 했다」에 해당하는 것. 대안과 이유를 함께
   - 액션: 담당자와 기한이 있는 것
   - 사실 변경: 기존 노트의 필드를 바꿔야 하는 것
   - 신규 개체: 볼트에 아직 노트가 없는 조직·제품·기술
3. 뽑은 것을 표로 보고한다. 파일은 아직 만들지 않는다.
4. 승인을 받은 뒤에만 노트를 만들거나 고친다.
5. 만든 노트에는 _ops/templates/ 의 해당 템플릿을 쓴다.
6. 마지막에 원문 노트의 「여기서 나온 가공물」 절에 링크를 추가한다.

## 규칙
- 새로 만든 노트는 confidence: draft 로 만든다
- 모든 가공물에 source: 로 원문을 링크한다
- 기존 노트와 모순되는 내용은 고치지 말고 「모순」으로 따로 보고한다
- 계약 전 고객은 confidential: 대외비 로 표시한다
- 모호한 것은 매끄럽게 정리하지 말고 「확인 필요」로 남긴다

## 산출물
- 원문 노트 1개 (수정 금지)
- 가공 노트 0개 이상
- 보고 표 (대화창)

## 하지 말 것
- 원문을 고치지 않는다. 오타와 비문도 그대로 둔다
- 원문에 없는 사실을 추론해 채우지 않는다
- 사람 이름은 원문 표기 그대로 쓴다. 직함을 추측해 붙이지 않는다
- confidence 를 reviewed 로 설정하지 않는다. 사람만 바꾼다
- 승인 없이 Sources/ 아래 파일을 만들거나 고치지 않는다

# 의도와 실행 대조 회고

## 언제 쓰나
- 분기 마지막 주 분기 회고
- 분기 계획을 중간에 고칠 때

## 입력
- 기간 (시작일과 종료일). 없으면 지난 분기로 한다

## 절차
1. Sources/40-Worklog/ 에서 해당 기간의 업무로그를 모은다.
2. 각 로그의 pdm_intent_of 링크를 따라가 대상 과제·기회 노트를 연다.
3. 과제별로 묶어 세 줄로 정리한다.
   - 계획: 그 과제 노트의 stage 와 due
   - 실제: 로그에 실제로 적힌 일
   - 차이: 둘이 어긋난 지점
4. pdm_intent_of 가 없는 로그는 「연결되지 않은 일」로 따로 모은다.
5. 로그가 없는 날은 「기록 없음」으로 표시한다. 추측해 채우지 않는다.

## 규칙
- 「한 일」이 아니라 「진척과 막힌 것」 중심으로 쓴다
- 차이를 발견하면 원인을 단정하지 않는다. 차이만 적는다
- 사람을 평가하는 문장을 쓰지 않는다. 이름과 사실만 쓴다
- 1500자 이내

## 산출물
- _reports/회고-YYYY-QQ.md
- 첫 줄에 지난 회차 대비 「연결되지 않은 일」의 증감을 적는다

## 하지 말 것
- Sources/ 아래의 노트를 고치지 않는다
- 로그가 비어 있으면 회고를 만들지 않는다. 「기록 없음」 한 줄만 남긴다
- 계획에 없던 일을 사후에 계획에 넣지 않는다

# 볼트 규약 점검

## 언제 쓰나
- 매월 첫 월요일
- 온톨로지 설계서를 고친 직후

## 입력
- _ops/01-온톨로지-설계서.md 와 _ops/02-표준용어집.md
- 없으면 시작하지 않는다

## 절차
1. _ops/scripts/validate.py 의 최근 결과를 먼저 읽는다.
   거기서 이미 잡힌 항목은 다시 보지 않는다.
2. 스크립트가 못 잡는 아래 네 가지만 본다.
   - 수치가 적혀 있는데 근거 노트 링크가 없는 경우

# frontmatter 를 읽어 단일 HTML 파일로 렌더링한다. 외부 라이브러리 없음.

import re, datetime
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
rows = []
for md in (ROOT / "Sources" / "20-Projects").glob("*.md"):
    text = md.read_text(encoding="utf-8")
    fm = re.match(r"---\n(.*?)\n---", text, re.S)
    if not fm:
        continue
    meta = dict(
        re.findall(r"^(\w+):\s*\"?([^\"\n]+)\"?$", fm.group(1), re.M)
    )
    rows.append((md.stem, meta.get("status", "미기재"),
                  meta.get("due", ""), meta.get("owner", "")))

rows.sort(key=lambda r: r[2] or "9999")
today = datetime.date.today().isoformat()

html = [f"<h1>과제 현황 <small>{today}</small></h1><table>"]
for name, status, due, owner in rows:
    d_day = ""
    if due:
        left = (datetime.date.fromisoformat(due) - datetime.date.today()).days
        d_day = f"D{left:+d}"
    cls = "urgent" if d_day and left < 21 else ""
    html.append(f"<tr class='{cls}'><td>{name}</td><td>{status}</td>"
                f"<td>{due} {d_day}</td><td>{owner}</td></tr>")
html.append("</table>")

(ROOT / "_reports" / "dashboard.html").write_text(
    "<style>.urgent{background:#FAEADF}</style>" + "\n".join(html),
    encoding="utf-8")

## 순서
1. 원문을 Sources/40-Worklog/2026-07-15-주간회의.md 로 먼저 저장한다.
   원문은 한 글자도 고치지 않는다. 오타도 그대로 둔다.
2. 원문에서 아래를 추출한다.
   - 결정(decision): 「~하기로 했다」에 해당하는 것. 대안과 이유를 함께 적는다
   - 액션(action): 담당자와 기한이 있는 것
   - 사실 변경: 기존 노트의 필드를 바꿔야 하는 것
   - 신규 개체: 볼트에 아직 노트가 없는 조직·제품·기술
3. 추출한 것을 표로 먼저 보여준다. 파일은 아직 만들지 않는다.
4. 내가 승인하면 노트를 만들거나 수정한다.

## 규칙
- 회의록에 없는 내용을 추론하지 않는다. 모호하면 「확인 필요」로 남긴다
- 「~같다」, 「~라고 함」처럼 불확실한 진술은 confidence: draft 로 표시한다
- 기존 노트와 모순되는 내용을 발견하면 고치지 말고 「모순」으로 따로 보고한다
- 사람 이름은 원문 표기를 그대로 쓴다. 직함을 추측해 붙이지 않는다
- 계약 전 고객의 이름은 confidential: 대외비 로 표시한다
