CHAPTER 13

팀으로 일하기: 멀티 에이전트 협업

Claude 하나로 부족하면, 여러 개를 동시에 돌리세요

1인 스타트업의 비밀

민수는 혼자서 사이드 프로젝트를 진행하고 있어요. 기획, 디자인, 프론트엔드, 백엔드, 테스트... 전부 혼자 해야 해요.

"팀원이 3명만 있으면 일주일이면 끝날 텐데..."

그래서 민수는 Claude를 3명 고용했어요. 터미널 3개를 열고, 각각 다른 역할을 맡겼어요. 결과? 하루 만에 끝났어요.

Claude Code는 하나만 실행할 수 있는 게 아니에요. 여러 터미널에서 동시에 실행하면, 마치 여러 명의 전문가가 동시에 일하는 것과 같아요.

이 장부터는 git을 조금 알아야 해요

12장까지는 Claude와 대화만 하면 됐는데, 이 장에는 git이라는 도구의 말이 섞여 나와요. 여럿이 같은 코드를 동시에 고칠 때 서로 밟지 않게 해주는 도구예요. 여기서는 그 「여럿」이 여러 개의 Claude죠. 아직 안 깔았다면 git-scm.com에서 받아 설치하세요.

깊이 알 필요는 없어요. 세 단어만 알면 이 장을 끝까지 따라올 수 있어요.

  • 커밋(commit) = 세이브 포인트. 지금 상태를 저장해 두는 거예요. 나중에 이 지점으로 돌아올 수 있죠
  • 브랜치(branch) = 평행 세계. 원래 코드는 그대로 두고 갈라져 나온 사본이에요. 여기서 마음껏 부숴도 원래 쪽은 멀쩡해요
  • PR(Pull Request) = 합치기 요청. 평행 세계에서 한 일을 원래 세계에 합쳐 달라고 내는 요청서예요. 합치기 전에 한 번 확인할 자리를 만들어 주죠

이 셋은 전부 Claude에게 시켜도 돼요. 「지금까지 한 거 커밋해줘」, 「feature/login 브랜치 만들어줘」처럼 말하면 Claude가 명령어를 대신 쳐요. 직접 외울 필요는 없고, 말이 나왔을 때 무슨 뜻인지만 알면 충분해요.

전략 1: 병렬 세션 · 여러 터미널에서 동시에

가장 간단한 방법이에요. 터미널을 여러 개 열고, 각각 Claude Code를 실행하면 돼요.

세 명의 Claude

터미널 1: 기획자 Claude
"우리 서비스의 사용자 플로우를 설계해줘. 로그인 → 대시보드 → 기능 사용 → 결과 확인 순서로."

터미널 2: 개발자 Claude
"로그인 페이지를 React로 구현해줘. 이메일/비밀번호 방식으로."

터미널 3: QA Claude
"기존에 만든 API 엔드포인트들을 테스트해줘. 모든 경우의 수를 커버하는 테스트 코드를 작성해."

이때 중요한 건 각 세션이 서로 다른 파일을 건드리게 하는 거예요. 같은 파일을 동시에 수정하면 충돌이 나니까요.

충돌 방지 원칙

각 Claude에게 담당 영역을 명확히 지정하세요:
- Claude A: src/frontend/ 폴더만 담당
- Claude B: src/backend/ 폴더만 담당
- Claude C: tests/ 폴더만 담당

마치 사무실에서 팀원들이 각자 자기 책상에서 일하는 것처럼요.

병렬 세션에서 유용한 슬래시 명령어들도 있어요:

  • /office-hours: 기획 모드. 아이디어를 구체화하고 전략을 세울 때
  • /qa: QA 모드. 체계적으로 버그를 찾고 테스트할 때
  • /review: 코드 리뷰 모드. 다른 세션에서 작성한 코드를 검토할 때

전략 2: Git Worktree · 독립된 작업 공간

Git Worktree는 같은 프로젝트를 여러 폴더에 복사하는 것과 비슷해요. 하지만 진짜 복사가 아니라, Git이 똑똑하게 관리해줘요.

Claude에게 이렇게 시키세요

"git worktree를 사용해서 feature-login 브랜치를 별도 폴더로 만들어줘. 그리고 그 폴더에서 로그인 기능을 구현해줘."

Worktree의 장점:

  • 각 기능을 완전히 독립된 공간에서 개발할 수 있어요
  • 한 기능이 망가져도 다른 기능에 영향이 없어요
  • 다 만들면 메인 브랜치에 합치기만 하면 돼요

Worktree를 쉽게 이해하기

내 프로젝트가 "집"이라고 상상해보세요.

보통 하는 방법: 한 집에서 주방 리모델링과 욕실 리모델링을 동시에 하면 → 혼란!

Worktree 방법: 주방 리모델링용 "가상의 집"과 욕실 리모델링용 "가상의 집"을 따로 만들어서, 각각 완성한 후에 원래 집에 반영해요. 깔끔하죠?

전략 3: 서브에이전트 · Claude가 Claude를 호출

이건 이름만 어렵지 손이 제일 덜 가요. Claude Code 안에서 Agent 도구를 사용하면, Claude가 다른 Claude를 불러서 일을 시킬 수 있어요.

마치 팀장이 "이 부분은 김 대리가 해줘"라고 업무를 위임하는 것처럼요.

메인 Claude (팀장): "전체 프로젝트를 관리하면서, 세부 작업을 각각 처리해줘"

→ 서브에이전트 1: 코드 구조 분석

→ 서브에이전트 2: 테스트 코드 작성

→ 서브에이전트 3: 문서 작성

메인 Claude가 결과를 취합해서 최종 보고

서브에이전트는 복잡한 작업을 자동으로 분할하고 처리해요. 터미널을 여러 개 직접 관리할 필요가 없어서 편하고, 따로 설정하지 않아도 Claude가 알아서 나눠 맡겨요.

협업 패턴: 어떻게 역할을 나눌까?

효과적인 역할 분담 패턴을 소개할게요:

패턴 1: 프론트엔드 / 백엔드 분리

  • Claude A: 사용자가 보는 화면 (HTML, CSS, React 등)
  • Claude B: 서버 로직, 데이터베이스, API
  • 둘 사이의 연결 규칙(API 스펙)을 미리 정해두면 충돌 없이 동시 작업 가능

패턴 2: 구현 / 리뷰 분리

  • Claude A: 기능 구현 (코드 작성)
  • Claude B: 코드 리뷰 (품질 검토, 보안 체크)
  • A가 만들면 B가 검토하고, 개선점을 A에게 전달

패턴 3: 기능별 분리

  • Claude A: 인증 시스템 (로그인, 회원가입)
  • Claude B: 핵심 기능 (대시보드, 데이터 처리)
  • Claude C: 부가 기능 (알림, 설정, 프로필)

브랜치 전략

멀티 에이전트로 일할 때는 각 Claude에게 별도 브랜치를 만들어주세요:
- feature/login: Claude A 담당
- feature/dashboard: Claude B 담당
- feature/notifications: Claude C 담당

다 완성되면 PR(Pull Request)로 메인 브랜치에 합치면 돼요.

실습: 두 개의 터미널에서 Claude 동시에 실행하기

  1. 터미널 두 개를 열어요 (VS Code에서 터미널 분할하면 쉬워요)
  2. 같은 프로젝트 폴더로 이동하세요
  3. 터미널 1에서: "index.html을 만들어줘. 간단한 할 일 목록 앱이야. UI만 먼저 만들어줘. style.css를 불러오는 <link> 태그를 넣어주고, 클래스 이름은 .todo-list와 .todo-item으로 해줘."
  4. 터미널 2에서: "style.css를 만들어줘. 할 일 목록 앱을 위한 깔끔한 스타일이야. 파란색 테마로. .todo-list와 .todo-item 두 클래스에 스타일을 넣어줘."
  5. 두 Claude가 동시에 일하는 걸 지켜보세요!
  6. 브라우저에서 index.html을 열어 보세요. 파란 스타일이 입혀져 있으면 성공이에요

3번과 4번에서 파일 이름과 클래스 이름을 미리 못 박은 게 이 실습의 전부예요. 앞에서 말한 「연결 규칙을 미리 정해두면 충돌 없이 동시 작업」의 가장 작은 실물이 이거죠.

정해주지 않으면 어떻게 되냐면, 두 세션은 서로의 대화를 모르니까 각자 다른 클래스 이름을 지어내요. index.html이 style.css를 불러오지도 않고요. 브라우저에서 열면 스타일이 하나도 안 먹은 맨 페이지가 나와요. 같은 파일을 안 건드리는 것만으로는 부족하고, 둘이 만나는 지점을 먼저 정해줘야 해요.

잠깐, 정리!

  • 병렬 세션: 터미널 여러 개에서 Claude Code를 동시에 실행하는 가장 간단한 방법
  • Git Worktree: 같은 프로젝트를 독립된 작업 공간에서 동시에 개발
  • 서브에이전트: Claude가 자동으로 작업을 분할하고 다른 Claude에게 위임
  • 핵심은 역할 분담과 충돌 방지예요. 각 Claude가 다른 파일/폴더를 담당하게 하세요
  • 브랜치 전략으로 안전하게 병합하세요
