CHAPTER 8

프로젝트 설정의 기술: CLAUDE.md와 컨텍스트

Claude에게 '우리 프로젝트'를 이해시키는 법

첫 출근한 신입사원의 고통

회사에 새 팀원이 합류했어요. 똑똑하고 열정적인 사람이에요. 그런데 첫날, 이 사람이 마주한 현실은...

"프로젝트 문서? 그런 거 없어요. 코드 보면서 파악하세요."

폴더 구조도 모르고, 코딩 규칙도 모르고, 뭘 건드리면 안 되는지도 모르고. 결국 이 신입사원은 2주를 헤매다가 겨우 첫 번째 코드를 작성해요. 그것도 팀 규칙을 몰라서 세 번이나 다시 고쳐야 했고요.

Claude Code도 마찬가지예요. 아무런 안내 없이 프로젝트에 투입하면, Claude는 나름대로 최선을 다하지만 내가 원하는 방식으로 일하지는 못해요.

해결책은 간단해요. 프로젝트의 "안내서"를 만들어주면 돼요. 그게 바로 CLAUDE.md예요.

CLAUDE.md: 프로젝트의 안내서

CLAUDE.md는 프로젝트 루트(최상위 폴더)에 놓는 특별한 파일이에요. Claude Code가 프로젝트를 열면 가장 먼저 읽는 파일이죠.

이 파일에 뭘 쓰느냐고요? 신입사원에게 알려줄 내용을 그대로 쓰면 돼요:

  • 이 프로젝트가 뭘 하는 건지 (프로젝트 설명)
  • 코드를 어떤 스타일로 작성해야 하는지 (코딩 컨벤션)
  • 어떤 기술을 사용하는지 (기술 스택)
  • 절대 하면 안 되는 것들 (주의사항)

실제 CLAUDE.md 예시

쇼핑몰 프로젝트의 CLAUDE.md를 한번 볼까요?

# 프로젝트: 온라인 쇼핑몰 "꿀샵"

## 프로젝트 설명
한국어 기반의 온라인 쇼핑몰 웹 애플리케이션입니다.
React + TypeScript로 프론트엔드, Express로 백엔드를 구성합니다.

## 기술 스택
- 프론트엔드: React 18, TypeScript, Tailwind CSS
- 백엔드: Express.js, Prisma ORM
- 데이터베이스: PostgreSQL
- 패키지 매니저: pnpm

## 코딩 규칙
- 컴포넌트는 함수형으로 작성 (class 컴포넌트 사용 금지)
- 변수명, 함수명은 영어 camelCase
- 주석은 한국어로 작성
- 커밋 메시지는 한국어로, "feat:", "fix:", "docs:" 접두사 사용

## 폴더 구조
- src/components/ : React 컴포넌트
- src/pages/ : 페이지 레벨 컴포넌트
- src/api/ : API 호출 함수
- server/ : 백엔드 코드

## 주의사항
- .env 파일은 절대 커밋하지 마세요
- 결제 관련 코드는 수정 전 반드시 확인 요청하세요
- 테스트 없이 main 브랜치에 직접 커밋하지 마세요

이렇게 작성해두면, Claude Code가 프로젝트의 맥락을 정확히 이해하고 우리 규칙에 맞게 코드를 작성해요.

비유로 이해하기

CLAUDE.md는 요리사에게 주는 레시피 노트예요. "우리 가게는 설탕 대신 꿀을 써요", "고추는 청양고추만 써요" 같은 규칙을 적어두면, 요리사가 매번 물어보지 않아도 우리 가게 스타일로 요리해줘요.

permissions.deny: "이건 읽지 마세요"

프로젝트 폴더에는 Claude가 보면 안 되는 파일들이 있어요. 비밀번호가 담긴 환경 변수 파일, 열쇠를 모아둔 폴더 같은 것들이요.

이걸 막는 자리는 .claude/settings.json이에요. 이 파일의 최상위 키 중 하나가 permissions이고, 그 아래 deny에 규칙을 적어요:

// .claude/settings.json
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)"
    ]
  }
}

여기서 중요한 건 순서예요. "파일을 하나 만들어두면 Claude가 알아서 안 봐요"가 아니라, "이 규칙을 넣으면 Claude가 그 파일 읽기를 거부해요"예요. 목록에 적힌 경로는 Claude Code가 읽으려다 말고 거부해요.

막고 싶은 경로가 더 있으면 같은 방식으로 deny 목록에 줄을 더하면 돼요. * 하나는 파일 이름 자리를, **는 하위 폴더까지를 뜻해요.

규칙을 넣었어도 확인하세요

보호는 규칙을 적은 만큼만 걸려요. 새 비밀 파일을 만들었다면 그 경로를 deny에 추가했는지 꼭 다시 보세요. 목록에 없는 파일은 그냥 읽힙니다.

메모리: Claude에게 기억시키는 법

메모리라고 하면 뭔가 따로 있는 것 같지만, 실체는 방금 배운 그 CLAUDE.md예요. 놓는 위치에 따라 적용 범위만 달라져요.

메모리 두 곳

  • 사용자 범위 (~/.claude/CLAUDE.md): 내 개인 선호도. 어느 프로젝트에서 일하든 따라와요
  • 프로젝트 범위 (./CLAUDE.md): 이 프로젝트에서만 적용되는 규칙. 팀과 함께 쓰는 자리죠

"나는 항상 한국어 주석을 선호해"는 사용자 범위에, "이 프로젝트는 Tailwind CSS를 쓴다"는 프로젝트 범위에 넣으면 돼요. 한 번 적어두면 매번 말할 필요가 없어져요.

기억은 내가 넣어요

Claude Code가 대화를 엿보다가 "이거 기억할까요?" 하고 먼저 물어보지는 않아요. 기억시키고 싶은 게 생기면 #으로 시작하는 줄을 입력하거나 /memory를 실행해서 직접 넣습니다. #을 쓰면 어느 범위에 저장할지 고르게 돼요.

여기에 더해 Claude Code가 스스로 남기는 auto memory도 있어요. 내가 손으로 적지 않아도 쌓이는 기록이니, 메모리가 위 두 CLAUDE.md뿐이라고 생각하면 안 돼요.

컨텍스트의 우선순위

Claude Code가 참고하는 정보에는 우선순위가 있어요. 어떤 게 더 중요하냐는 거죠.

현재 대화에서 직접 말한 것이 가장 높은 우선순위를 가져요. CLAUDE.md에 "변수명은 영어로"라고 써있어도, 대화에서 "이번에는 한국어 변수명 써줘"라고 하면 대화 내용을 따라요.

CLAUDE.md 작성 팁

1. 간결하게 쓰세요

Claude는 CLAUDE.md를 매번 읽어요. 10페이지짜리 문서를 써놓으면 매번 10페이지를 읽는 거예요. 핵심만 담고, 세부 사항은 별도 문서로 분리하세요.

2. 중요한 규칙은 CLAUDE.md에, 일시적인 건 대화로

"항상 TypeScript를 쓴다" → CLAUDE.md에
"이번에만 JavaScript로 해줘" → 대화에서 직접

3. 구체적으로 쓰세요

모호한 CLAUDE.md

"코드를 깔끔하게 작성하세요"

구체적인 CLAUDE.md

"함수는 30줄을 넘지 않도록 작성. 한 함수는 한 가지 역할만 담당. ESLint 규칙을 반드시 통과할 것."

시나리오: React + TypeScript 프로젝트의 CLAUDE.md

# 프로젝트: 꿀샵 프론트엔드

## 핵심 규칙
- React 18 + TypeScript strict mode
- 컴포넌트: 함수형만 사용, Props는 interface로 정의
- 스타일: Tailwind CSS (인라인 style 금지)
- 상태관리: Zustand (Redux 사용 금지)
- API 호출: React Query 사용

## 파일 네이밍
- 컴포넌트: PascalCase (ProductCard.tsx)
- 유틸리티: camelCase (formatPrice.ts)
- 테스트: [파일명].test.tsx

## 절대 하지 말 것
- any 타입 사용 금지
- console.log 커밋 금지
- 하드코딩된 API URL 금지

직접 해보기: 나의 CLAUDE.md 만들기

  1. 자신의 프로젝트 폴더(또는 아무 폴더)로 이동하세요
  2. CLAUDE.md 파일을 만드세요
  3. 다음 내용을 채워보세요:
    • 프로젝트 이름과 설명 (한 줄)
    • 사용하는 기술 스택
    • 코딩 규칙 3개 이상
    • "하지 말 것" 1개 이상
  4. Claude Code를 실행해서 "이 프로젝트에 대해 설명해줘"라고 물어보세요
  5. Claude가 CLAUDE.md를 잘 이해했는지 확인하세요!

이번 챕터 정리

  • CLAUDE.md는 Claude가 프로젝트를 이해하는 "안내서"예요. 프로젝트 루트에 놓으면 자동으로 읽어요.
  • .claude/settings.json의 permissions.deny 규칙을 넣으면 Claude가 그 파일 읽기를 거부해요.
  • 메모리는 곧 CLAUDE.md예요. 사용자 범위(~/.claude/CLAUDE.md)와 프로젝트 범위(./CLAUDE.md)로 나뉘고, #이나 /memory로 직접 넣어요.
  • 컨텍스트는 대화 > settings.json > CLAUDE.md 메모리 순으로 우선순위가 있어요.
  • CLAUDE.md는 간결하고 구체적으로 작성하세요.

다음 챕터 미리보기

CLAUDE.md가 프로젝트의 규칙을 알려주는 거라면, Skills는 Claude에게 전문적인 능력을 가르치는 거예요. 슬래시 하나로 코드 리뷰 전문가, 보안 감사관, QA 테스터를 소환할 수 있어요.
