CHAPTER 10

Hooks: AI의 행동을 자동화하다

Claude가 무언가를 할 때마다 자동으로 실행되는 마법

자동으로 된다면 얼마나 좋을까

Claude에게 파일을 수정시켰어요. 그런데 저장된 코드를 보니 들여쓰기가 엉망이에요. "아, 포맷팅 해줘" 하고 다시 요청해요.

코드를 커밋하려고 했더니, 린트 에러가 5개나 있어요. "에러 고쳐줘" 하고 또 요청해요.

이런 반복이 매일 수십 번 일어나요. 생각해보면 이건 항상 똑같은 패턴이에요:

  • 파일 저장 → 포맷팅
  • 코드 변경 → 린트 검사
  • 커밋 전 → 테스트 실행

매번 수동으로 요청하는 게 아니라, 자동으로 되면 안 될까?

네, 됩니다. 그게 바로 Hooks예요.

Hooks란 뭔가요?

Hooks는 Claude Code가 어떤 도구를 사용하기 전이나 후에 자동으로 실행되는 명령어예요.

자동문 센서를 생각해보세요

마트의 자동문 있잖아요. 센서가 사람을 감지하면 문이 열리고(PreToolUse), 사람이 지나가면 문이 닫혀요(PostToolUse). 매번 손으로 문을 열 필요 없이, 특정 상황이 되면 자동으로 실행되는 거예요. Hooks도 같은 원리예요.

예를 들어:

  • Claude가 파일을 저장하기 전에 → 자동으로 코드 검사
  • Claude가 파일을 저장한 후에 → 자동으로 코드 포맷팅
  • Claude가 위험한 명령어를 실행하기 전에 → 자동으로 차단

가장 많이 쓰는 Hook 3가지

Hook이 걸리는 이벤트는 이 셋 말고도 더 있어요. UserPromptSubmit, Stop, SessionStart, PreCompact 같은 것들이죠. 여기서는 처음 쓰기 좋은 세 가지만 볼게요.

1. PreToolUse: 도구 사용 전에 실행

Claude가 어떤 도구(파일 쓰기, 명령어 실행 등)를 사용하려고 할 때, 그 전에 실행돼요.

  • 위험한 명령어를 차단할 때 사용
  • 특정 파일 수정을 막을 때 사용
  • 입력값을 검증할 때 사용

2. PostToolUse: 도구 사용 후에 실행

Claude가 도구를 사용한 직후에 실행돼요.

  • 저장된 파일을 자동 포맷팅할 때 사용
  • 변경 사항을 알림으로 보낼 때 사용
  • 결과를 로그에 기록할 때 사용

3. Notification: 알림이 필요할 때

Claude가 사용자에게 승인을 요청할 때 실행돼요.

  • 모바일 알림 보내기
  • 소리 알림 울리기

Hook 설정하기

Hooks는 .claude/settings.json 파일에서 설정해요. 프로젝트 폴더 안의 .claude 폴더에 이 파일을 만들면 돼요.

기본 구조

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "echo '파일이 저장되었습니다!'"
          }
        ]
      }
    ]
  }
}

이 설정을 풀어보면:

  • "PostToolUse"는 도구를 쓴 다음에 실행하라는 뜻이에요
  • "matcher": "Write"는 "Write(파일 쓰기)" 도구가 걸렸을 때라는 조건이에요
  • "command"는 그때 자동으로 실행할 명령어예요

matcher 종류

matcher에는 Claude가 사용하는 도구 이름을 넣어요:

  • Write: 파일 쓰기
  • Edit: 파일 수정
  • Bash: 터미널 명령어 실행
  • Read: 파일 읽기

Hook 명령어는 stdin으로 정보를 받아요

예시로 넘어가기 전에 하나만 짚고 갈게요. Hook 명령어는 어떤 파일이 저장됐는지, 어떤 명령어가 실행될 참인지를 표준 입력(stdin)으로 들어오는 JSON으로 받아요. 대략 이런 모양이에요:

{
  "tool_name": "Bash",
  "tool_input": {
    "command": "rm -rf build"
  }
}

그래서 Hook 스크립트는 INPUT=$(cat)으로 이 JSON을 읽고, 그 안에서 필요한 값을 꺼내 써요. 한 줄짜리 명령어로 쓰기엔 길어지니까, 앞으로의 예시는 .claude/hooks/ 폴더에 셸 스크립트를 두고 settings.json이 그 스크립트를 가리키게 할게요.

스크립트를 만들면 실행 권한을 주세요

스크립트 파일을 만든 다음에는 chmod +x .claude/hooks/스크립트이름.sh를 한 번 실행하세요. 실행 권한이 없으면 Hook이 조용히 실패해요.

실전 Hook 예시들

예시 1: 파일 저장 후 자동 포맷팅

Prettier로 코드를 자동 정리해요. 먼저 settings.json에서 스크립트를 가리켜요:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/format.sh"
          }
        ]
      }
    ]
  }
}

그리고 .claude/hooks/format.sh를 이렇게 만들어요:

#!/bin/bash
INPUT=$(cat)
FILE=$(printf '%s' "$INPUT" | python3 -c 'import sys,json; print(json.loads(sys.stdin.read()).get("tool_input",{}).get("file_path",""))')
if [ -n "$FILE" ]; then
  npx prettier --write "$FILE"
fi

예시 2: 위험한 명령어 차단

rm -rf 같은 위험한 명령어를 막아요. settings.json은 이렇게 써요:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/block-danger.sh"
          }
        ]
      }
    ]
  }
}

.claude/hooks/block-danger.sh의 내용이에요:

#!/bin/bash
INPUT=$(cat)
CMD=$(printf '%s' "$INPUT" | python3 -c 'import sys,json; print(json.loads(sys.stdin.read()).get("tool_input",{}).get("command",""))')
if echo "$CMD" | grep -q 'rm -rf'; then
  echo "위험한 명령입니다" >&2
  exit 2
fi

여기서 exit 2가 핵심이에요. 이 종료 코드가 도구 실행을 실제로 차단해요.

예시 3: 커밋 전 테스트 자동 실행

settings.json은 예시 2와 같은 모양이고, command만 .claude/hooks/test-before-commit.sh로 바꿔요. 스크립트는 이렇게 써요:

#!/bin/bash
INPUT=$(cat)
CMD=$(printf '%s' "$INPUT" | python3 -c 'import sys,json; print(json.loads(sys.stdin.read()).get("tool_input",{}).get("command",""))')
if echo "$CMD" | grep -q 'git commit'; then
  npm test
  if [ $? -ne 0 ]; then
    echo "테스트가 실패해서 커밋을 막았어요" >&2
    exit 2
  fi
fi

시나리오: 프로덕션 DB 접근 차단 Hook

실수로 프로덕션 데이터베이스에 손대는 걸 막아주는 Hook이에요. .claude/hooks/block-prod.sh를 만들고, PreToolUse의 Bash matcher에 연결하세요:

#!/bin/bash
INPUT=$(cat)
CMD=$(printf '%s' "$INPUT" | python3 -c 'import sys,json; print(json.loads(sys.stdin.read()).get("tool_input",{}).get("command",""))')
if echo "$CMD" | grep -qE 'prod|production'; then
  echo "프로덕션 환경 접근이 차단되었어요. 개발 환경을 쓰세요" >&2
  exit 2
fi

이 Hook이 있으면, Claude가 실수로 프로덕션 서버에 명령어를 실행하려고 해도 자동으로 차단돼요. 안전하죠!

Hook 사용 팁

간단한 것부터 시작하세요

처음부터 복잡한 Hook을 만들지 마세요. echo로 메시지를 출력하는 것부터 시작하고, 점점 기능을 추가해나가세요.

PreToolUse로 실수를 방지하세요

PostToolUse는 "이미 실행된 후"예요. 실수를 막으려면 PreToolUse를 쓰세요. 잘못된 명령어가 실행되기 전에 차단하는 게 훨씬 안전해요.

exit 코드로 차단하세요

PreToolUse Hook에서 exit 2를 반환하면 차단, exit 0이면 통과예요. exit 1은 "차단하지 않는 오류"라서 도구가 그대로 실행되니 조심하세요.

Hook = 자동 품질 관리

Hooks를 잘 설정하면, Claude가 일할 때마다 자동으로 품질 검사가 이루어져요. 마치 공장에서 제품이 컨베이어 벨트를 따라 이동하면서 자동으로 검수받는 것처럼요. 수동 검수보다 빠르고, 놓치는 것도 없어요.

직접 해보기: 첫 번째 Hook 설정

  1. 프로젝트 폴더에 .claude 폴더를 만드세요 (없으면)
  2. .claude/settings.json 파일을 만드세요
  3. 아래 내용을 넣어보세요: 
    {
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "echo '파일이 저장됨: 확인 완료!'"
          }
        ]
      }
    ]
  }
}
  4. Claude Code를 실행하고 "hello.txt 파일을 만들어줘"라고 요청하세요
  5. 파일이 저장된 후 자동으로 메시지가 출력되는지 확인하세요!

이번 챕터 정리

  • Hooks는 Claude의 도구 사용 전/후에 자동으로 실행되는 명령어예요.
  • PreToolUse는 실행 전(검증/차단), PostToolUse는 실행 후(포맷팅/알림)에 사용해요.
  • .claude/settings.json에서 설정하고, matcher로 어떤 도구에 반응할지 정해요.
  • 실전 활용: 자동 포맷팅, 위험 명령어 차단, 커밋 전 테스트, DB 접근 제한 등.
  • 간단한 Hook부터 시작해서 점점 기능을 추가하세요.

다음 챕터 미리보기

Hooks가 Claude의 행동을 자동화하는 거라면, MCP 서버는 Claude의 능력 자체를 확장하는 거예요. 이메일 보내기, 데이터베이스 조회, 웹 크롤링까지. Claude에게 새 초능력을 하나씩 붙여주는 거죠.
