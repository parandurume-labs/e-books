CHAPTER 16

나만의 워크플로 만들기

CLAUDE.md + Skills + Hooks + MCP = 나만의 AI 팀

퍼즐 조각을 맞추는 시간

이 책을 다 읽으셨다면, 이제 여러분의 손에는 여러 개의 퍼즐 조각이 있어요:

CLAUDE.md라는 조각, Skills라는 조각, Hooks라는 조각, MCP라는 조각...

각각은 이미 유용하지만, 이것들을 조합하면 진짜 마법이 일어나요. 마치 레고 블록 하나하나는 그냥 플라스틱이지만, 조합하면 성이 되고 로봇이 되듯이요.

이번 마지막 챕터에서는 모든 조각을 맞춰서 나만의 워크플로를 만드는 방법을 알아볼게요.

빌딩 블록 복습

조합하기 전에, 각 조각이 뭐였는지 빠르게 복습해볼게요:

네 가지 빌딩 블록

CLAUDE.md — 프로젝트의 맥락과 규칙
"이 프로젝트는 뭐하는 거고, 이런 규칙을 따라야 해"를 Claude에게 알려주는 설명서.

Skills — 전문가 역할
Claude에게 특정 전문성을 부여하는 스킬. /review, /ship, /qa 같은 슬래시 명령어로 호출.

Hooks — 자동화 트리거
"파일을 저장하면 자동으로 테스트 실행", "커밋하면 자동으로 린트 체크" 같은 자동화 규칙.

MCP — 외부 시스템 연결
GitHub, Microsoft Teams, 데이터베이스 등 외부 서비스와 Claude를 연결하는 다리.

각각만 써도 좋지만, 조합하면 100배가 돼요. 진짜로요.

워크플로 예시 1: 블로그 작성자

블로그 작성자의 AI 워크플로

  1. MCP (RSS 서버) — 관심 분야 RSS 피드에서 최신 기사 수집
  2. Claude 분석 — 수집된 기사에서 트렌드와 흥미로운 주제 추출
  3. Skills (/write-post) — 선택한 주제로 블로그 초안 생성 (나의 문체, 블로그 형식에 맞춰서)
  4. 내가 편집 — 초안을 읽고, 내 의견과 경험을 추가
  5. Hooks (자동 저장) — 파일 저장 시 자동으로 마크다운 검증 + 맞춤법 체크
  6. MCP (GitHub) — 완성된 글을 블로그 저장소에 자동 커밋 + 배포

결과: 예전에 하루 걸리던 블로그 포스팅이 2시간이면 완성돼요.

이 워크플로에서 CLAUDE.md에는 이런 내용이 들어가요:

# 내 블로그 프로젝트

## 블로그 정보
- 주제: 기술 트렌드, AI 활용법
- 대상 독자: IT에 관심 있는 비개발자
- 문체: 친근하고 쉬운 한국어, ~요 체

## 글 작성 규칙
- 제목은 호기심을 자극하되 과장하지 않기
- 전문 용어는 처음 등장 시 설명
- 실제 사용 예시 반드시 포함
- 글 길이: 1500-2000자

워크플로 예시 2: 프리랜서 개발자

프리랜서 개발자의 AI 워크플로

  1. CLAUDE.md — 고객 요구사항, 기술 스택, 코딩 컨벤션 정리
  2. Skills (/plan) — 요구사항을 바탕으로 구현 계획 수립
  3. 코딩 — Claude Code로 기능 구현 (한 번에 하나씩)
  4. Skills (/review) — 구현된 코드 자체 리뷰
  5. Hooks (자동 테스트) — 파일 수정 시 관련 테스트 자동 실행
  6. Skills (/ship) — 테스트 통과 후 PR 생성 + 변경사항 문서화
  7. MCP (GitHub) — PR 생성, 리뷰 요청

결과: 혼자 일해도 팀으로 일하는 것 같은 품질 관리가 가능해요.

워크플로 예시 3: 스타트업 창업자

스타트업 창업자의 AI 워크플로

  1. gstack 전체 관리 — 프로젝트 구조, 빌드, 배포를 하나의 시스템으로
  2. 병렬 세션 — 터미널 3개: 프론트엔드 / 백엔드 / QA
  3. CLAUDE.md — 비즈니스 목표, MVP 범위, 우선순위 정리
  4. Skills (/office-hours) — 주간 스프린트 계획, 우선순위 조정
  5. MCP (Teams) — 주요 이벤트(빌드 성공, 에러 발생) 시 Teams 알림
  6. Hooks (자동 배포) — main 브랜치 머지 시 자동 배포 트리거

결과: 혼자서 5인 팀 수준의 개발 속도를 낼 수 있어요.

나만의 워크플로 설계하기

이제 여러분의 워크플로를 직접 설계해볼 차례예요. 다음 단계를 따라가세요:

Step 1: 반복하는 업무 목록 작성

일주일 동안 하는 일 중에서 반복되는 것들을 적어보세요.

  • 매일 하는 일: 이메일 확인, 일일 보고 작성, 코드 리뷰...
  • 매주 하는 일: 주간 보고서, 스프린트 계획, 블로그 포스팅...
  • 가끔 하는 일: 제안서 작성, 발표 자료 준비, 신규 기능 개발...

Step 2: 각 업무에 맞는 도구 선택

목록의 각 항목에 가장 적합한 빌딩 블록을 매칭하세요:

  • 매번 같은 방식으로 해야 하는 일 → Skills로 표준화
  • 자동으로 실행되어야 하는 일 → Hooks로 자동화
  • 외부 서비스와 연동이 필요한 일 → MCP로 연결
  • 맥락이 중요한 일 → CLAUDE.md에 정리

Step 3: CLAUDE.md에 워크플로 문서화

CLAUDE.md에 추가할 내용

"CLAUDE.md에 나의 워크플로 섹션을 추가해줘. 매일 아침 하는 루틴: 1) 이메일 확인 및 분류, 2) 일일 보고 초안 작성, 3) 오늘의 우선순위 정리. 각 단계에서 사용하는 스킬과 도구도 같이 적어줘."

Step 4: Skills / Hooks / MCP 설정

문서화한 워크플로를 실제로 구현하세요. Claude에게 하나씩 만들어달라고 하면 돼요.

Step 5: 테스트 및 개선

한 번에 완벽할 필요 없어요. 일주일 써보고, 불편한 점을 고치세요. 이 반복이 여러분의 워크플로를 점점 더 강력하게 만들어줘요.

100배의 시작은 1배부터

이 책의 제목은 "Claude 100배 활용법"이에요. 하지만 솔직히 말씀드리면, 100배는 하루아침에 오지 않아요.

현실적인 성장 곡선

1주차: Claude.ai에서 기본 대화. 효율 2배.
2주차: 프롬프트가 늘어남. 효율 5배.
1개월: Claude Code + Skills 활용. 효율 10배.
3개월: Hooks + MCP + 나만의 워크플로. 효율 30배.
6개월: 모든 것이 자연스러워짐. 효율 50배.
1년: AI와 함께 일하는 게 당연해짐. 효율 100배.

작은 것부터 시작하세요. 오늘 이메일 하나를 Claude로 작성해보세요. 내일은 보고서 초안을 시켜보세요. 모레는 새로운 스킬을 하나 만들어보세요.

이 책의 핵심 메시지

AI는 검색 도구가 아니라, 지시를 통한 업무 달성 도구예요.

"어떻게 하면 돼요?"라고 묻지 말고,
"이것을 해주세요"라고 지시하세요.

여러분의 시간은 소중해요. 반복적인 일은 Claude에게 맡기고, 여러분은 정말 중요한 일에 집중하세요. 판단하고, 결정하고, 창조하는 일. 그건 여전히 여러분의 몫이에요.

Claude는 도구예요. 아무리 좋은 도구라도, 쓰는 사람의 의도와 판단이 있어야 가치가 있어요. 여러분이 방향을 정하고, Claude가 속도를 내는 거예요.

이 책을 읽어주셔서 감사해요. 여러분의 100배 여정이 오늘부터 시작되길 바랍니다.

전체 책 요약

  • 제1부: AI는 검색이 아닌 지시 도구. 구체적으로, 맥락을 주면서 지시하세요
  • 제2부: Claude.ai로 대화, Claude Desktop으로 내 컴퓨터와 연결
  • 제3부: Claude Code로 개발 생산성 폭발. CLAUDE.md, Skills, Hooks, MCP가 핵심 도구
  • 제4부: 실전 워크플로 — 앱 만들기, 멀티 에이전트 협업, 보안 관리
  • 제5부: 생태계 탐험과 나만의 워크플로 설계. API, Agent SDK, 커뮤니티 활용
  • 핵심: 작은 것부터 시작하고, 점진적으로 확장하세요. AI는 도구이고, 판단은 여러분의 몫이에요
