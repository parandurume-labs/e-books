CHAPTER 14

보안과 안전: Claude를 믿되, 검증하라

강력한 도구일수록 안전하게 써야 합니다

칼은 요리사의 도구

요리사에게 칼은 없어서는 안 될 도구예요. 하지만 칼을 다룰 때는 조심해야 하죠. 칼날이 날카로울수록 더 좋은 요리를 만들 수 있지만, 동시에 더 조심해야 해요.

Claude도 마찬가지예요. 파일을 수정하고, 명령어를 실행하고, 코드를 배포할 수 있는 강력한 도구예요. 강력하기 때문에, 안전하게 쓰는 방법도 알아야 해요.

이번 챕터는 Claude를 겁내라는 게 아니에요. 제대로 쓰는 방법을 알아보는 거예요.

권한 시스템: Claude가 물어보는 이유

Claude Code를 쓰다 보면, 가끔 이런 질문을 받아요:

Claude의 질문

"이 파일을 수정해도 될까요?"
"이 명령어를 실행해도 될까요?"
"이 패키지를 설치해도 될까요?"

Claude가 이렇게 물어보는 이유는, 쓰는 사람의 의도를 확인하기 위해서예요. 실수로 중요한 파일을 삭제하거나, 위험한 명령어를 실행하는 걸 막아주는 안전장치죠.

Claude Code에는 권한 모드가 여러 개 있어요 (2026년 7월 확인):

  • default: 위험할 수 있는 작업마다 물어봐요. 가장 안전한 기본값이에요
  • acceptEdits: 파일 수정은 묻지 않고 바로 진행해요. 명령어 실행은 여전히 물어봐요
  • plan: 계획만 세우고 파일을 건드리지 않아요. 무엇을 할지 먼저 보고 싶을 때 좋아요
  • auto: 대부분 알아서 진행해요. 빠르지만 눈을 떼면 안 돼요
  • dontAsk: 물어보지 않고 진행하되, 막힌 곳은 그냥 넘어가요
  • bypassPermissions: 아무것도 묻지 않아요. 편리하지만 그만큼 위험해요

여섯 개나 되지만 처음에는 default와 plan 둘만 알면 충분해요. 나머지는 손에 익은 뒤에 골라 쓰세요.

그럼 이 모드를 어디서 바꾸냐고요? Claude Code를 시작할 때 옵션으로 붙여요. 계획만 세우게 하고 싶으면 터미널에서 이렇게 실행하세요:

claude --permission-mode plan

plan 자리에 default, acceptEdits, auto, dontAsk, bypassPermissions를 넣으면 그 모드로 시작해요. 아무것도 안 붙이고 그냥 claude를 실행하면 default예요. 지금까지 이 책에서 해온 게 전부 default였던 거죠.

추천 설정

초보자: default로 쓰세요. 어떤 작업이 벌어지는지 자연스럽게 배우게 돼요.
중급자: 무엇을 할지 먼저 보고 싶으면 plan, 파일 수정이 잦으면 acceptEdits.
고급자: 신뢰하는 개인 프로젝트에서만 bypassPermissions를 쓰고, 프로덕션 환경에서는 default로 돌아오세요.

민감 정보: 절대 공유하면 안 되는 것들

Claude는 내 컴퓨터의 파일을 그대로 읽어요. 그래서 민감한 정보가 든 파일은 미리 보호해야 해요.

절대로 하지 말아야 할 3가지

1. API 키나 비밀번호를 프롬프트에 직접 입력하지 마세요
"이 API 키로 연결해줘: sk-abc123..." 이렇게는 절대 안 돼요!

2. .env 파일을 Claude가 읽게 두지 마세요
.env 파일에는 보통 비밀번호, API 키, 데이터베이스 접속 정보가 들어있어요.

3. 개인정보가 포함된 데이터를 그대로 전달하지 마세요
고객 이름, 전화번호, 주민등록번호 등이 포함된 파일은 익명화한 후에 사용하세요.

deny 규칙으로 파일 보호하기

프로젝트의 .claude/settings.json에 permissions.deny 규칙을 적으면, Claude가 특정 파일을 읽지 못하게 막을 수 있어요. 파일 내용은 이렇게 써요:

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)"
    ]
  }
}

Read(...) 안에는 경로 패턴을 적어요. **는 하위 폴더까지 전부라는 뜻이에요. 보호하고 싶은 파일이 더 있으면 "Read(./credentials.json)", "Read(./*.pem)"처럼 줄을 추가하면 돼요.

.env 파일 활용법

비밀 정보는 .env 파일에 넣고, 코드에서는 환경 변수로 참조하세요:

이렇게 하세요

"API 연동 코드를 만들어줘. API 키는 환경 변수 OPENAI_API_KEY에서 가져오도록 해. .env 파일의 내용은 보여주지 않을게."

이렇게 하면 Claude는 API 키 자체를 모른 채로 안전한 코드를 써줘요.

비용 관리: 현명하게 사용하기

Claude는 "토큰"이라는 단위로 사용량을 측정해요. 토큰은 대략 한국어 기준으로 한 글자가 1-2 토큰 정도예요 (2026년 7월 확인).

비용이 걱정된다면 이런 방법들이 있어요:

/cost: 현재 비용 확인

대화 중에 /cost를 입력하면 현재 세션에서 쓴 토큰과 비용이 바로 나와요.

비용 절약 팁

  • compact 모드 활용: 대화가 길어지면 /compact를 입력해서 이전 대화를 요약하세요. 불필요한 컨텍스트를 줄여서 토큰을 절약해요
  • 불필요한 파일 제외: permissions.deny에 "Read(./node_modules/**)", "Read(./dist/**)" 같은 큰 폴더를 추가하세요. Claude가 읽을 파일이 줄어들면 토큰도 절약돼요
  • 구체적으로 요청: "전체 코드를 검토해줘"보다 "src/auth.js의 login 함수만 검토해줘"가 토큰을 덜 써요
  • 새 세션 시작: 주제가 완전히 바뀌면 새 세션을 시작하세요. 이전 대화 맥락을 유지할 필요가 없으니까요

안전 모드: 더 조심하고 싶을 때

9장에서 소개한 gstack에는 여러 안전 모드가 있어요. 설치했다면 상황에 따라 이렇게 쓰세요:

gstack 안전 모드 가이드

/careful: 주의 모드
위험할 수 있는 명령어(rm -rf, DROP TABLE 등)를 실행하기 전에 경고해줘요. "이 명령어는 데이터를 삭제할 수 있어요. 정말 실행할까요?"

/freeze [경로]: 파일 수정 범위 제한
특정 폴더만 수정할 수 있게 제한해요. 예: /freeze src/이면 src 폴더 밖의 파일은 수정 불가.

/guard: 최대 안전 모드
/careful + /freeze를 합친 거예요. 프로덕션 환경에서 작업할 때 사용하면 좋아요.

언제 gstack 안전 모드를 쓸까?

평상시: 기본 권한 확인으로 충분해요
중요한 프로젝트: /careful 사용을 추천해요
프로덕션 서버 작업: /guard 필수! 실수 한 번이 큰 사고로 이어질 수 있어요
디버깅 중: /freeze로 수정 범위를 문제 파일로 제한하세요

안전 사용 체크리스트

Claude 안전 사용 Best Practices

  1. permissions.deny 설정: 민감 파일을 미리 제외하세요
  2. API 키는 환경 변수로: 코드에 직접 넣지 마세요
  3. git commit 자주 하기: 문제가 생기면 이전으로 돌아갈 수 있게
  4. 권한 요청 꼼꼼히 읽기: 특히 처음에는 "뭘 하려는 건지" 확인하세요
  5. 프로덕션 환경에서는 gstack의 /guard 사용: 안전이 최우선
  6. /cost로 비용 모니터링: 예상치 못한 과금 방지
  7. 결과물 검증: Claude가 만든 코드를 배포 전에 반드시 확인하세요
  8. 개인정보 익명화: 실제 데이터 대신 샘플 데이터를 사용하세요

실습: deny 규칙으로 민감 파일 막기

  1. 프로젝트 폴더의 루트(최상위)로 이동하세요
  2. Claude Code에게 이렇게 말하세요:
    ".claude/settings.json에 permissions.deny 규칙을 추가해줘. Read(./.env), Read(./secrets/**), Read(./*.pem)을 막도록."
  3. 생성된 .claude/settings.json을 열어서 규칙이 제대로 들어갔는지 확인하세요
  4. 테스트: 임시로 .env 파일을 만들고 Claude Code를 다시 시작한 다음, ".env 파일 내용을 읽어줘"라고 해보세요. Claude가 거부하면 성공!
  5. 테스트 파일은 삭제하세요

이 한 번의 설정으로, 앞으로 실수로 민감 정보가 노출되는 일을 예방할 수 있어요.

잠깐, 정리!

  • Claude의 권한 시스템은 실수를 방지하는 안전장치예요. 귀찮아도 초보자는 매번 확인하세요
  • API 키, 비밀번호, 개인정보는 절대로 직접 전달하지 마세요
  • .claude/settings.json의 permissions.deny로 민감 파일을 Claude가 못 읽게 막으세요
  • /cost로 비용을 모니터링하고, /compact로 토큰을 절약하세요
  • 위험한 작업에는 gstack의 /careful, /freeze, /guard 안전 모드를 활용하세요
