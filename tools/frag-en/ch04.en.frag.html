Teams / OneDrive: delivery

You are probably already using it. If your company runs Microsoft 365, this costs nothing extra.

Teams does exactly one thing here. You make one shared folder in Teams and it syncs automatically to everyone's PC. When someone edits a note, it shows up on the other machines within minutes.

Why this is good

  • Your company accounts already handle permissions. One account per person controls access. No new accounts to create.
  • Backup is automatic. OneDrive version history rolls a file back.
  • Offboarding is easy. Disable the account and access stops.
  • Zero extra cost. You use what you already have.

What it costs you

Two problems come with it. Chapter 6 covers them properly, but here is the warning up front.

Problem 1 · cloud-only files

By default OneDrive keeps files in the cloud and downloads one only when you open it. File Explorer shows the file, but it is not actually on the PC.

For a person opening notes in Obsidian this causes no trouble, because opening a note downloads it. The AI, though, reads only what is really on disk. So you end up in the situation where the file is right there and the AI cannot read it.

The fix is one right-click on the folder, then "Always keep on this device." It is the single most important click in this book.

Problem 2 · edit conflicts

When two people edit the same note at once, OneDrive makes a conflict copy named something like filename 1.md. There is no live merge the way Google Docs does it.

Technology will not stop this. An operating rule will. Divide up who owns which axis, and let only the author edit their own worklog. Chapter 6 goes through how to split the work.

It does not have to be Teams

Google Drive works. Dropbox works. Even a GitHub repository works. Anything that syncs files to several PCs will do the job. Each one behaves a little differently, though.

OptionUpsideDownside
Teams / OneDriveTies into company permissions. No extra costThe cloud-only file trap. No conflict merge
Google DriveFamiliarNeeds the desktop sync app. Conflicts behave the same way
DropboxThe most reliable syncingPaid. Permissions become a separate job
Git (GitHub and friends)Merges conflicts properly. Perfect change historyA steep wall for non-developers

On technical merit alone Git wins. With non-developers on the team it is hard in practice. If every note means a commit and a push, three minutes a day turns into ten, and then nobody does it. Sustainability matters more than technical superiority.

Obsidian: the window

Obsidian is an app that shows markdown files as a wiki. It is free, and it does not take your data to its own servers.

What Obsidian does

  • Wikilinks. Write [[Warebot]] and you get a link to that note.
  • Backlinks. It shows you every other note pointing at this one, automatically. This matters more than it sounds.
  • Graph view. It draws the connections between notes. Orphaned notes stand out at a glance.
  • Fast search. It searches the whole vault instantly.

What Obsidian does not do

This part matters more. Obsidian does not lock your data into its own format.

The real reason for this combination

Your knowledge stays as plain text files. If Obsidian disappears, if the company switches tools, if the AI changes, the files still open.

With Notion or another SaaS wiki, the data sits on their servers in their format. Export exists, and the structure breaks on the way out. Putting your company's core knowledge in someone else's format is a risk.

But do we really need Obsidian

If your company already runs on Microsoft 365, this question comes up on its own. You have Teams and OneDrive, and here is one more app to install.

The honest answer: this system runs without Obsidian.

Look at what actually does the work in this book. Cowork reads the files in the folder directly (Chapter 7). The check scripts read files (Chapter 17). The script that draws the dashboard only looks at frontmatter (Chapter 15). Power Automate reads through SharePoint (Chapter 14). None of the four goes through Obsidian. A [[Warebot]] is just characters on a line, so the AI follows that link with no Obsidian anywhere in sight.

So what does Obsidian do. It lets a person see the graph. That is all it does, and it earns its place doing it.

Drop Obsidian and you loseWhat you do instead
Clicking a link to move aroundSearch by filename. Slower, but it works
Backlinks (the list of notes pointing at this one)Write a script. Nothing appears on its own
Graph viewGone. This is how Pickview shows up as an isolated dot in Chapter 5
Links following a renameRename in Explorer or SharePoint and every link breaks (Appendix C)

That last row hurts the most in practice. Note names change more often than you would think.

Being removable is the argument for it

This book does not recommend a tool like Notion, because the data ends up locked in someone else's format. Hold Obsidian to that same standard and the fact that you lose nothing by removing it is a passing grade. The vault is a folder. The notes are text files.

So put it this way. Take away sync (Teams/OneDrive) or Cowork and the system stops. Take away Obsidian and it keeps running. It is free and it locks up nothing, so there is no particular reason to take it away either.

One caution. A tool that saves in its own format, like OneNote or Loop, cannot stand in for Obsidian. That is not swapping the window; that is throwing out the premise of this book.

You do not need plugins

Obsidian has a huge community plugin ecosystem, AI plugins included. This book uses none of them.

There is a reason. While building this system we did install an LLM wiki plugin, and we pulled it back out three weeks later. Chapter 13 walks through that call in detail. The core reasons were these.

  • The AI model the plugin used did not understand our ontology.
  • It generated English notes from Korean sources, so company names came out translated and distorted.
  • By design it would produce low-quality duplicate notes competing with the human-verified ones.
  • Claude Cowork did the same job better.

Plugins are not the problem. The lesson is that when two tools do the same job, you end up trusting neither.

Claude Cowork: the hands

This is where the system gets its actual power.

Claude Cowork is a feature of the Claude desktop app, and it reads and writes folders on your computer directly. You do not upload files into a chat window. It reaches the folder itself.

Upload versus folder access

File upload (ordinary chat)Folder access (Cowork)
ScopeThe few files you pickedThe whole folder
Search everythingNoYes, regular expressions included
Editing filesNo. You get a new file and save it yourselfEdits in place
Batch work across filesNoYes
Running codeNoYes, Python scripts and the like
Re-uploading every timeRequiredNot needed

The third and fifth rows are the decisive ones. The AI writes code and runs it against the vault. Quality checks, bulk edits and link analysis all come out of that.

Solbit Tech in practice: day one

On the day Solbit Tech first set this up, here is what Claude did.

  • Swept the whole vault folder and mapped the structure of 105 existing files
  • Created 40 files: the ontology design doc, the glossary, the operating guide, 7 templates and more
  • Wrote a Python quality-check script and ran it → found 19 rule violations
  • Fixed all 19 in one pass and ran it again → 0 left

Watch the third and fourth items. The AI checked its own output. There really were a few YAML syntax mistakes, and the script caught them.

File uploads cannot do this. There is no way to run the code.

What Cowork cannot do

The limits, honestly.

The question everyone asks: "do we have to build an MCP?"

Read around this topic and MCP (Model Context Protocol) comes up. It is a standard for connecting AI to outside tools and services. Several MCP servers for Obsidian are already public.

So this question comes up a lot. "Should we install an Obsidian MCP? Should we build our own?"

The answer: not yet

An Obsidian vault is just a pile of markdown files. Cowork handles the folder directly, so you do not need an MCP to get access. Direct file access is the stronger option anyway. Whole-vault search, running code and bulk editing are slow through MCP tool calls, or simply impossible.

There are cases where MCP genuinely pays off, though.

SituationWhat to pick
You want to read and write the vault on a PCCowork folder access. No MCP needed
You want to look the vault up from mobile or ordinary chatA community MCP (the Local REST API family)
You want rule violations blocked up front instead of caught afterwardsBuild your own MCP

The third is the only one with a real payoff. An MCP server enforces "reject anything malformed" without exception. If the AI forgets the rule, the server still stops it.

Build this after you have watched the problem, not before. Design a system for a problem you have not met yet and you build what you do not need while missing what you do. Run the vault for two or three weeks and you will have data on how often the rules actually break. Decide then.

How this book leans

Use few tools. If one will do, use one.

Knowledge systems most often die not from too few tools but from too much to maintain. Install five plugins, three MCPs and ten automation scripts, and six months later maintaining them is the job.

It looks like a lot, and most of it you build once and never touch again. What you use every day is the axis folders inside Sources/.

Try it: check your setup

Run through this before you move on to Part 2.

  1. Does your company run Microsoft 365? If not, Google Drive or Dropbox stands in fine. Decide which one now.
  2. Does everyone work from a desktop or a laptop? Anyone who lives on a tablet or a phone will end up reading in Obsidian and nothing more.
  3. Do you have an account that can use the Claude desktop app? If not, sort that out first.
  4. Name one knowledge owner. This is the person who designs the ontology and runs the weekly check. Usually it is the CEO, but if someone on the team enjoys organizing documents, they are the better pick.

Quick recap

  • The three tools share one single folder. No server, no database, no integration setup
  • Teams/OneDrive = delivery. Your company accounts already handle permissions and backup. In exchange you get the cloud-only file trap and edit conflicts
  • Obsidian = the window. Wikilinks, backlinks, graph view. Above all it leaves your data as plain text files
  • Claude Cowork = the hands. Direct folder access. Whole-vault search, bulk edits and running code

  • You do not need MCP yet. If access is the goal, direct folder access is stronger. Revisit it when you need violations blocked up front
